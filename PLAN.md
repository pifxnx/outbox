План проекта: заказы с Kafka и transactional outbox
Цель: написать небольшое приложение, которое принимает заказы, надёжно публикует события в Kafka и обрабатывает их идемпотентно.
Стек
- Python
- PostgreSQL
- Kafka
- Docker Compose
Что реализовать
1. Поднять инфраструктуру
   Настроить Docker Compose для PostgreSQL и Kafka.
2. Создать API заказов
   Сделать POST /orders, который сохраняет заказ в PostgreSQL.
3. Добавить transactional outbox
   В одной транзакции записывать заказ и событие OrderCreated в таблицу outbox. Так событие не потеряется, если запись заказа прошла успешно.
4. Публиковать события в Kafka
   Сделать фоновый процесс, который читает неопубликованные записи из outbox, отправляет их в Kafka и помечает опубликованными.
5. Обработать событие идемпотентно
   Consumer читает OrderCreated и в одной транзакции PostgreSQL проверяет event_id, сохраняет его в processed_events и меняет состояние заказа. Повторная доставка того же события не должна повторно применить изменения.
6. Добавить миграции и конфигурацию
   Описать таблицы orders, outbox, processed_events через миграции. Параметры подключения хранить в конфигурации приложения.
7. Проверить сценарии отказа
   Убедиться, что заказ и outbox-запись сохраняются атомарно, события публикуются после перезапуска, а дубликат события не приводит к повторной обработке.
Основной сценарий
POST /orders → транзакция PostgreSQL (orders + outbox) → Kafka → consumer → идемпотентное обновление в PostgreSQL.

API, outbox-publisher и consumer можно запустить как отдельные процессы или контейнеры из одного проекта.
